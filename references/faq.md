# 元钥常见问题

## 速查索引

- **扫描**：扫目录没发现 · git 历史怎么扫 · 跳过哪些文件
- **判定**：误报怎么办 · 默认打码 · verify 是联网查吗
- **报错**：退出码 · git 不可用
- **安装**：智能体目录 · 和元史/元情分工

---

## 1. 目录里明明有密钥，为什么扫出来 0 条？

先确认路径确实被扫描（`--path` 指向文件或目录）且文件未在跳过名单（`.git`、`node_modules`、二进制、`.npmignore`/`.gitignore` 排除项）。再确认值符合规则长度/格式；若密钥是无前缀的高熵 token，需要启用 `generic` 类并用较高长度阈值判定。

## 2. 输出为什么默认打码？

防止结果本身造成二次泄露。打码只保留头尾（如 `ghp_****abcd`）；确需明文给 CI/轮换脚本用 `--show-secret`，但应只在受控环境使用。

## 3. verify 会联网验证密钥是否有效吗？

不会。`verify` 只在本机用正则 + 熵 + 格式校验判断“像不像某类密钥”，不连接任何服务、不查询泄露库、不发送数据。

## 4. 误报很多怎么办？

先用 `entropy` 看值的信息熵，再用 `verify` 看命中规则；占位符/示例值/环境变量引用会自动过滤。仍误报的可结合 `--types` 缩小类别，或用 `--exclude` 排除已知测试目录。

## 5. 如何扫描 git 历史？

在仓库内执行 `scan --git --path repo/`，引擎用 `git log -p` 只扫新增行并附 commit 与文件路径。非 git 仓库会返回退出码 4 并提示。

## 6. 为什么有些高熵字符串没被标成密钥？

`generic` 是兜底类，需满足长度、熵、非纯哈希/非 UUID/非已知文件路径等条件，且按 medium 置信提示人工复核。纯十六进制哈希、badge URL、git clone URL 等常见干扰会被过滤。

## 7. JSON/CSV 里字段怎么用？

`rule_id/rule_name/category/severity/file/line/secret/entropy/length/snippet/commit` 都可用于 CI 门禁、工单复现或元盾拦截。要直接拿整条结果做自动化前，先让人工确认一次真阳性率。

## 8. 退出码 0/1/4 是什么意思？

`scan` 未发现疑似密钥为 0；发现为 1；用法错误、路径不存在、git 不可用等为 4。`verify` 0=未命中、1=命中、4=用法错误。`mask/entropy` 成功均为 0。

## 9. 发现疑似密钥后我该做什么？

不要只删代码。先确认是否真实，再按顺序处理：轮换/吊销该凭据、从活跃代码移除、从 git 历史清理或标注泄露，最后补密钥管理（环境变量/密钥库/最小权限）。本技能只定位，不自动轮换。

## 10. 安装不上/智能体没识别怎么办？

用 `npx -y @yottameta/yotta-secret --agent <名称>` 或 `--dir <技能目录>`；npm 镜像传播延迟时临时用 `--registry=https://registry.npmjs.org/`。装完后新会话才会自动加载。

## 11. 元钥和元史 mask 有什么区别？

元钥是“源头扫描 + 打码”的超集：定位代码/配置/git 历史里的凭据；元史负责日志检索时的输出脱敏。两者共享同源词库规则，可组成“扫描源头 + 检索输出都脱敏”的闭环。

## 12. 元钥和元情怎么分工？

元钥扫“本地文件/配置/git 历史里的疑似凭据”；元情从“威胁报告/邮件/日志文本”提取 IOC。凭据出现在情报文本里也可用元钥打码，但 IOC 提取/defang 归元情。
